# Qubix — Quiz Platform

Qubix — REST API-платформа для создания и прохождения тестов. Система позволяет пользователям проходить тесты, а авторам — создавать и управлять категориями, тестами, вопросами и вариантами ответов.

## Технологии

- **Go** — язык программирования.
- **net/http** — HTTP-сервер и маршрутизация.
- **PostgreSQL** — реляционная база данных.
- **database/sql + lib/pq** — работа с базой данных.
- **JWT** — аутентификация и авторизация.
- **bcrypt** — безопасное хеширование паролей.
- **OpenAPI / Swagger Editor** — документация и тестирование API.

## Архитектура проекта

Проект построен на трёхслойной архитектуре:

- **Handler** — принимает HTTP-запросы, взаимодействует с сервисами и возвращает HTTP-ответы.
- **Service** — содержит бизнес-логику, проверки и основные операции приложения.
- **Repository** — отвечает за взаимодействие с PostgreSQL.

Дополнительно используются:

- **Model** — внутренние модели данных приложения.
- **DTO (Data Transfer Object)** — структуры для приёма и передачи JSON-данных через API.
- **Middleware** — проверка JWT-токенов и контроль доступа.
- **App** — инициализация компонентов приложения и настройка зависимостей.

## Основные возможности

### Аутентификация и авторизация

- Регистрация пользователей.
- Вход в систему.
- Хеширование паролей с помощью bcrypt.
- Генерация и проверка JWT-токенов.
- Разграничение прав доступа по ролям `user` и `author`.
- Защита приватных маршрутов с помощью middleware.

### Управление тестами

- Создание и управление категориями.
- Создание и управление тестами.
- Добавление и редактирование вопросов.
- Добавление и управление вариантами ответов.
- Управление собственными материалами автора.

### Прохождение тестов

- Создание попытки прохождения теста.
- Отправка ответов на вопросы.
- Завершение попытки.
- Подсчёт результата.
- Получение итогового результата.

Правильные ответы не раскрываются в публичных ответах API.

## База данных

Проект использует PostgreSQL.

База данных состоит из 9 основных таблиц:

1. `users`
2. `categories`
3. `quizzes`
4. `questions`
5. `options`
6. `attempts`
7. `answers`
8. `answer_options`
9. `results`

Между таблицами настроены внешние ключи для обеспечения целостности данных.

ER-диаграмма базы данных находится в папке `docs`.

## Установка и запуск

### 1. Клонирование проекта

```bash
git clone https://github.com/BahodurSolizoda/qubix.git
cd qubix
```

### 2. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example`.

Пример:

```env
PORT=8080
DATABASE_URL=postgres://username:password@localhost:5432/qubix?sslmode=disable
JWT_SECRET=your_secret_key
```

Укажите собственные данные PostgreSQL и секретный ключ JWT.

### 3. Установка зависимостей

```bash
go mod tidy
```

### 4. Подготовка базы данных

Создайте базу данных PostgreSQL с именем `qubix`.

Выполните SQL-миграции из папки `migrations` в правильном порядке.

При необходимости используйте SQL-файлы из папки `seeds` для добавления начальных данных.

### 5. Запуск сервера

```bash
go run ./cmd/api
```

После успешного запуска сервер будет доступен по адресу:

```text
http://localhost:8080
```

## API и Swagger

В проекте подготовлена спецификация OpenAPI в файле `openapi.yaml`.

Для просмотра документации и отправки запросов через браузер используется [Swagger Editor](https://editor.swagger.io/).

### Подключение Swagger Editor

1. Запустите Qubix:

   ```bash
   go run ./cmd/api
   ```

2. Откройте [Swagger Editor](https://editor.swagger.io/).

3. Импортируйте файл `openapi.yaml`.

4. Для защищённых запросов получите JWT-токен через `POST /login`.

5. Нажмите **Authorize** в Swagger Editor.

6. В поле `BearerAuth` вставьте полученный токен.

7. Для проверки доступа выполните запрос `GET /private` через **Try it out → Execute**.

При корректном токене сервер должен вернуть:

```text
Access granted!
```

### CORS

Для взаимодействия со Swagger Editor настроен CORS.

Разрешены следующие HTTP-методы:

- GET
- POST
- PUT
- DELETE
- OPTIONS

Также разрешены необходимые заголовки:

- Authorization
- Content-Type
- Accept

Swagger Editor и OpenAPI были добавлены как дополнительная инициатива автора проекта, сверх основных требований.

## Безопасность

- Пароли хранятся в виде bcrypt-хешей.
- Защищённые маршруты требуют JWT-токен.
- Проверяются роли и права доступа пользователей.
- Автор может управлять только собственными материалами.
- Правильные ответы скрыты от пользователей до проверки результата.
